# MediGuide: Medicine & Symptom Information Assistant

## Abstract
MediGuide is an educational agentic application that explains a limited set of medicines, reports known interaction warnings, looks up a brand-ingredient example, and retrieves source-linked health information. A LangGraph workflow screens each request before tool use. A custom MCP server exposes three medicine tools. A Gemini-powered ReAct researcher can use these tools alongside local retrieval and Tavily web search. Emergency phrases interrupt the workflow and display guidance immediately. Source-backed response construction and explicit unknown results limit unsupported claims. The system is a capstone prototype, not a clinically validated assistant.

## Problem and objective
General web searches can mix trustworthy medicine information with inaccurate advice. Users may mistake a missing interaction result for proof that a combination is safe. This project demonstrates how structured tools, retrieval, routing and escalation can make an educational information workflow more inspectable. The intended users in the brief are the general public, caregivers and pharmacy students; actual clinical use is outside this prototype's validated scope.

## Design
The Streamlit UI submits a question and optional structured fields. The Guardrail Agent screens their combined text locally. Emergency matches route to an interrupt; diagnosis and treatment requests route to a scope response. Other requests route to Info or Interaction. These agents invoke the separate MCP subprocess, then retrieve relevant knowledge chunks. Research runs in offline or live mode, and the Evidence Response Agent assembles linked records and passages.

The shared state carries the query, intent route, medicine names, brand variant, retrieved documents, MCP findings, web results, audit trace, warnings and answer. Credentials remain in the graph's server-side closure and are not placed in the shared state or downloads.

## MCP service
The server implements the standard stdio transport with the Python MCP SDK. Each client session initializes the protocol and calls the relevant tool. `drug_info` returns uses, common side effects, warnings and a source. `check_interaction` examines all supplied pairs; only explicitly supported pairs produce a warning, while all others are unknown. `find_generic` accepts an exact US Tylenol Regular Strength tablet example and returns its ingredient with source and pharmacist-confirmation language.

## RAG pipeline
Seven short, original summaries are stored as JSON chunks with stable IDs, URLs and a review date. A TF-IDF vectorizer indexes title and text using unigram/bigram features. Cosine similarity ranks candidates; results below 0.10 are excluded and at most three are selected. The response is generated by structured, extractive assembly with source links beside each passage. This deliberately avoids unconstrained medical synthesis. The local dataset is small, so lexical mismatch can produce weak retrieval; expanding and clinically reviewing the corpus is future work.

## Agent behavior
In live mode, Gemini receives a research-only system prompt and five tool schemas. It emits tool calls, the harness executes at most two per turn, and observations return as ToolMessages. The loop ends when the model finishes or after four turns. This is the ReAct action-observation pattern implemented explicitly rather than relying on a deprecated agent factory. The application does not expose private model reasoning or treat research completion text as clinical advice. A deterministic Tavily fallback ensures current-information requests attempt search even if Gemini fails to choose the tool.

## Safety and human-in-the-loop
English regular expressions detect a limited set of red-flag phrases. The escalation node calls LangGraph `interrupt()` with guidance and source links. The UI renders that payload before asking for acknowledgement. `Command(resume=True)` closes the emergency query; there is no return to medicine processing. No clinician or dispatcher receives a message. The prototype does not offer a staffed human escalation service.

This screening is conservative and incomplete. Quoted or negated red flags can over-trigger. Unusual descriptions can be missed. Prompt constraints, domain filtering and constrained response construction reduce some failure modes but cannot establish clinical safety. The included evaluation is explicitly illustrative and must not be represented as clinical validation.

## Web search and privacy
Tavily search restricts results to WHO, NHS, FDA, CDC and MedlinePlus domains. URLs are checked after retrieval as well. Results are source links with retrieval timestamps; finding no result is not proof of no advisory. Search excerpts are short and treated as untrusted data. The user must allow external transmission before normal live-mode requests. Keys are entered via environment variables or password fields and are not included in source code.

## Testing and results
See VALIDATION.md for executed tests and guardrail_evaluation.json for all evaluation cases, including failures. Tests cover the actual stdio transport, workflow routing, emergency interrupts and terminal resumption, source retrieval, incomplete interaction coverage, provider-unavailable behavior, mocked ReAct iteration limits and Streamlit interactions. Live API calls cannot be validated without the user's credentials; these are not claimed as tested.

## Limitations and future work
The medicine catalogue, interaction table and generic lookup are intentionally small, as permitted by the brief's curated mock dataset option. There is no patient history, dose engine, prescribing function or full drug-interaction database. Add licensed comprehensive drug data, clinician-maintained knowledge, independently evaluated multilingual red-flag models, source freshness checks, stronger evidence selection and a staffed escalation pathway before considering broader use. Production privacy, security, regulatory and clinical review would be separate work.

## Conclusion
MediGuide supplies a runnable, inspectable example of MCP tools, retrieval, ReAct and LangGraph orchestration for a medicine-information task. Its strongest feature is explicit boundaries: source-linked information, unknown results, and emergency interruption. It should be presented as an educational engineering demonstration.
